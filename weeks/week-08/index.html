Recall and Apply

Definitions and Formulas

Important Definitions

parity
Extra bit indicating whether the number of one bits should be even or odd.
checksum
Compact value computed from data to detect some accidental changes.
CRC
Polynomial-based error-detection code effective at detecting common burst errors.
codeword
Complete transmitted block containing data and any added coding bits.
Hamming distance
Number of bit positions in which two equal-length codewords differ.
FEC
Added redundancy that lets a receiver correct some errors without retransmission.
interleaving
Reordering bits from different codewords to spread burst damage before decoding.
coding gain
Reduction in required energy-per-bit to noise-density ratio for a stated target error rate under specified coding and decoding conditions.
coded bit rate
Transmitted bit rate including the extra bits added by error-control coding.
information bit rate
Rate of information bits carried by the code, before other overhead and retries.
secret key
A value kept from outsiders. In our shared-key example, the controller and door store it beforehand; they do not send it with the command.
message authentication code (MAC)
A cryptographic check calculated from a message and a secret key. It supports integrity and message authentication. This is not a network interface's MAC address.
authentication tag
The value produced by the MAC calculation and sent with the message. The receiver recalculates the expected tag and compares them.
integrity
Protection against changes or forged content going undetected.
message authentication
Evidence that a message was formed by a holder of the trusted key. If several devices share a key, this does not distinguish those devices or the people using them.
authorization
Permission to perform a particular action, such as opening a particular door. Authentication and authorization are different checks.
replay
Recording a valid message and sending that same message again later.
freshness
Evidence that a message belongs to the current exchange rather than being a reused old message. Our simple counter rule rejects previously accepted commands; it does not prove wall-clock age.
counter
An increasing message number. In the ordered, single-controller example, the receiver requires a protected number larger than the last one accepted and remembers the new value.
plaintext / ciphertext
The readable message / its encrypted form.
encryption / decryption
Using a key to transform readable content into ciphertext / recovering the readable content with the appropriate key.
confidentiality
Keeping content from observers who should not read it.
authenticated encryption
An established encryption method that also protects integrity and message authenticity. Replay and permission checks are still needed.
metadata
Visible traffic details, such as transmission times and lengths, even when content is encrypted.
whitelist
A list of values the device accepts. Approving a CRC value does not identify a sender.
CRC collision
Different messages produce the same CRC value.
ASK (amplitude-shift keying)
Digital modulation using carrier-amplitude states.
OOK (on-off keying)
An ASK case using carrier absent/present as two states.
FSK (frequency-shift keying)
Digital modulation using carrier-frequency states.
PSK (phase-shift keying)
Digital modulation using carrier-phase states.
BPSK (binary phase-shift keying)
Two opposite phase states, carrying one bit per symbol.
QPSK (quadrature phase-shift keying)
Four phase states, carrying two bits per symbol.
QAM (quadrature amplitude modulation)
Digital modulation using combinations of amplitude and phase; 16-QAM has 16 states and four bits per symbol.
constellation
Diagram of allowed or measured symbol states in in-phase and quadrature coordinates.
symbol
One selected signaling state in a symbol interval, which can represent one or more bits.
baud
Symbols per second; not necessarily bits per second or transitions per second.
I/Q (in-phase/quadrature)
Signed weights on same-frequency carrier components 90 degrees apart; their combination describes one carrier state.
spectral efficiency
Stated gross or useful bit rate divided by occupied bandwidth.

Equations and Relationships

  • Code rateRc = k / n
  • Redundancyn - k bits
  • Information bit rateRinfo = Rcoded × Rc
  • Random-remainder approximationPundetected ≈ 1 / 2r
  • CRC boundarya matching public CRC does not establish an authenticated sender.
  • CRC recomputationa changed message can have a newly calculated matching CRC; its value may change.
  • Collision boundarydifferent messages can have the same CRC, so approving a CRC value does not uniquely approve a command or identify its sender.
  • MAC relationshipmessage + secret key → authentication tag. The message and tag travel; the key stays secret.
  • Replay boundaryan old message can still have a valid tag. Protect the counter with the message and check remembered receiver state.
  • Permission boundarya valid tag does not authorize every action.
  • Encryption boundaryencryption alone does not necessarily detect changes or reject replay; timing and message length may remain visible.
  • Physical boundaryan authenticated sensor message does not prove that the sensor measured physical reality accurately.
  • Bits per symbolbits per symbol = log2(M)
  • Mapped bit rateRb = Rs log2(M), for fixed-length binary labels with M a power of two
  • Required symbol rateRs = Rb / log2(M)
  • Information bit rateRinfo = Rb Rc, where Rb is the mapped/coded rate and Rc is the code rate; ignore other overhead and retries only when stated
  • Spectral efficiencyeta = stated bit rate / occupied bandwidth; state whether the rate is gross or useful
  • Comparison assumptionat equal average symbol energy, denser BPSK/QPSK/16-QAM constellations have smaller minimum point spacing
