Recall and Apply

Definitions and Formulas

Important Definitions

line coding
Representation of bits by signal levels or transitions.
Manchester coding
The course convention has a midpoint rise for 1 and a midpoint fall for 0.
OOK
On-off keying: an amplitude-shift-keying option that switches the carrier on and off.
FSK
Frequency-shift keying: representing digital states using different carrier frequencies.
identifier
A device or interface label; observing it does not prove who transmitted it.
beacon
An announcement used to discover a device or service; it is not proof of identity.
CRC
Cyclic redundancy check: an error-detection check that is not keyed sender authentication.
message authentication code (MAC)
A keyed tag used to check message authenticity and integrity; not a network MAC address.
nonce
A value used once in a protocol context; the illustrative challenge is newly chosen for each request.
authentication
Checking evidence that a message or participant is genuine under the chosen trust model.
freshness
Evidence that a message belongs to the current exchange rather than an earlier captured exchange.
replay
Reuse of a previously valid transmission at a later time.
relay attack
Forwarding a current exchange between legitimate endpoints so that distance or the apparent path is misleading.
proximity
Physical nearness; neither an identifier nor a valid response alone establishes it.
distance bounding
A protocol and hardware timing check designed to bound how far away a responding device can be.
BLE
Bluetooth Low Energy; LE 1M/2M examples use GFSK and connected frequency hopping.
GFSK
Gaussian frequency-shift keying: FSK with shaping to control the transmitted spectrum.
UWB
Ultra-wideband; used for secure ranging in the selected phone-key architecture.
NFC
Near-field communication; supports the selected digital-key architecture’s tap-based access option.
CCTV / DVR
Closed-circuit television / digital video recorder: the recorder stores feeds from security cameras.
bootloader
Software that runs early in startup and loads the operating system; a boot console may accept configuration commands.
root shell
An operating-system command interface with the highest administrative privileges on the studied Linux device.
ASCII
American Standard Code for Information Interchange: maps characters to numeric values; the examples put its seven-bit codes in eight-bit data fields.
byte
Eight bits; its interpretation may be a character, number or part of a binary message.
UART
Universal asynchronous receiver/transmitter: sends and receives framed serial data without a shared clock wire.
TX / RX
Transmit output / receive input. A transmitter connects to a compatible receiver input.
NRZ
Non-return-to-zero: no mandatory neutral return within each bit. The selected logic-level UART uses LOW=0 and HIGH=1.
baud
Signaling symbols per second. In the selected binary UART, one symbol carries one bit.
8N1
Eight data bits, no parity bit, one stop bit; one start bit precedes the data.
start bit
A LOW interval after idle HIGH that aligns reception of an idle-high UART frame.
stop bit
A HIGH interval ending the selected UART frame; it is not a checksum or authentication check.
LSB first
Least-significant data bit is sent first. Reverse the data field when writing conventional MSB-first binary, not the entire frame.
MSB
Most-significant bit: the highest-weight bit of the data value.
parity
An optional basic error-detection bit; N in 8N1 means it is absent.
logic-level UART
An interface using levels relative to its supply and ground; examples include 3.3 V and 5 V devices with device-specific limits.
TTL
Transistor-transistor logic; TTL UART is common shorthand for a logic-level interface, not a guarantee of voltage compatibility.
RS-232
An electrical interface with bipolar data levels: logical 1 is negative and logical 0 is positive.
framing efficiency
The fraction of frame bits in the data field under the stated definition of payload.
debug console
A maintenance interface that displays diagnostic text or accepts commands; access depends on firmware protections.
client
Computer or application requesting a service or file.
server
Computer or application providing the requested service or file.
Ethernet
Rules for transmitting frames over wired links; Internet access is not required.
frame
Bounded data unit with delivery information, carried data and an error check.
payload
Data carried inside a frame; it can include other protocol headers as well as file data.
switch
Device connecting Ethernet links and forwarding a known destination toward its associated port.
port
Connection point for a link on a switch or other device, in this physical-link discussion.
LAN
Local area network, connecting communicating devices within a local network.
topology
Arrangement of devices and links; this lecture’s switch-centered arrangement is a star.
MAC address
Media Access Control link-interface address, distinct from a keyed authentication code.
FCS
Frame check sequence, a CRC-based error check that does not authenticate a sender.
network tap
Hardware providing a capture view of traffic crossing the link where it is installed.
metadata
Observable addressing, frame lengths, timing or direction apart from protected file content.
TLS
Transport Layer Security, used to protect application communication; HTTPS uses TLS.

Equations and Relationships

  • Frame airtimeTframe = N / Rb
  • Trust boundaryvisible identifier does not equal authenticated identity
  • Replay resistancefreshness must be protected and checked against the current request
  • Binary UART bit durationTb = 1 / Rb
  • Complete frame intervalsNf = Nstart + Ndata + Nparity + Nstop
  • Frame durationTf = Nf / Rb
  • Ideal character rateRchars = Rb / Nf
  • Data-field efficiencyefficiency = Ndata / Nf
  • Frame-only serialization timeT = 8 × complete frame bytes / line bit rate
  • Frame-only ideal frame rateframes/s = line bit rate / complete frame bits
  • Ethernet-payload fractionpayload bytes / complete frame bytes × 100%
