Line Coding and Radio Reception

Read line-coded data on an oscilloscope, find AM/DSB, USB and LSB signals using WebSDR, and choose a cellular receiver location using signal-quality evidence

Learning Outcomes

By the End of This Lab

  • Decode characters from line-coded signals and identify the line coding used for a known message
  • Find separate AM/DSB, USB and LSB transmissions using WebSDR and record their frequencies and receiver locations
  • Distinguish DSB with a carrier from USB and LSB using the spectrum and audio together
  • Analyze a three-day cellular backup-link log in Excel and recommend a placement using radio quality and timely alert delivery

The Big Picture

What You Are Doing

  1. Work through three independent activities; your assigned group determines the order.
  2. Use a Nano and oscilloscope to observe line-code references and identify the coding of a known message.
  3. Find three signals in WebSDR: ordinary AM (DSB with a carrier), USB and LSB.
  4. Investigate a supplied workplace report and 1,296 cellular test records to choose a backup-gateway antenna location. No phone is required.

Before Lab

Preparation

  • Open the linked WebSDR Signal Guide in your browser and have headphones ready.
  • Have Arduino IDE available. Use the preloaded Nano; open Serial Monitor at 115200 baud with Newline selected.
  • Review the Lecture 25 line-code conventions and this week’s spectrum, propagation and cellular-quality terms.
  • Open the report and supplied cellular dataset. Follow your assigned activity order; the WebSDR guide gives receiver links and search steps.

Bench Setup

Equipment and Materials

  • Browser with internet access and headphones for WebSDR

Follow These Steps

Lab Walkthrough

1. Read the Line Codes — Table 1

Evidence Photo

Save the four reference captures, a full CYBER327 capture and a close-up of its beginning. Show both channels, time scale and frame marker.

  1. Connect the preloaded Nano to USB. Select its port in Arduino IDE, open Serial Monitor at 115200 baud with Newline selected, and send HELP. Leave the firmware installed.
  2. Use two 10× probes and set both scope channel probe factors to 10×. Connect both ground clips to Nano GND. Connect CH1’s tip to D9 (encoded data) and CH2’s tip to D2 (frame-start marker).
  3. Enable both channels in Normal time mode with DC coupling. Start at 2 V/div and 10 ms/div. Position both traces so you can distinguish LOW near 0 V from HIGH near 5 V using each channel’s zero reference.
  4. Set Trigger to Edge, source 2, rising slope. Turn the physical Trigger Level knob until the upper-right readout is about 2 V. Choose Horiz → Time Ref → Left and set horizontal delay to 0 s. Keep at least eight divisions to the right of the trigger.
  5. Send FRAME REF and CODE NRZ-L, one command per line. For this practice, the Nano repeatedly sends ASCII “3”. The CH2 pulse marks the start of the frame. Each data bit lasts 10 ms; bytes are sent MSB first. The initial level for NRZ-M/S is LOW. Use Run/Stop to freeze a capture, or Single to acquire the next frame.
  6. Align the start of your capture with the frame marker, then record the levels for each bit interval in Table 1. Save the NRZ-L reference capture.
  7. Send CODE NRZ-M. Capture the signal and record its levels. Decode the eight bits, determine the ASCII character and record both in Table 1. Save the image.
  8. Send CODE NRZ-S. Capture the signal and record its levels. Decode the eight bits, determine the ASCII character and record both in Table 1. Save the image.
  9. Send CODE MANCHESTER. Capture the signal and record its half-bit pairs. Decode the eight bits, determine the ASCII character and record both in Table 1. Save the image.
  10. Send FRAME UNKNOWN. The Nano now repeatedly sends the known message CYBER327 using a line coding scheme to identify. Set the scope to 100 ms/div and capture the complete 640 ms message, aligned with the CH2 frame-start pulse. Then set 10 ms/div and acquire another frame-start capture for a close-up of the first byte.
  11. Known message: ASCII CYBER327. Hex bytes, in order: 43 59 42 45 52 33 32 37. Each byte is sent MSB first; the message contains 64 bits.
  12. Use the known message and your captures to identify the coding scheme. Record your result and transition evidence in Table 1.
  13. Before leaving, send FRAME REF and CODE NRZ-L and restore 10 ms/div. Disconnect the scope probes and leave the board ready for the next group.

2. Find AM / DSB, USB and LSB Signals — Table 2

Evidence Photo

Save three spectrum/waterfall screenshots: AM / DSB, USB and LSB. Show readable frequencies and modes; caption each with receiver identity, location and observation time.

  1. WebSDR — start here. Open Northern Utah WebSDR. Find three separate intelligible transmissions: ordinary AM (DSB with a carrier), USB and LSB. Ordinary AM supplies the DSB example; it is not a fourth required signal.
  2. Choose a receiver covering the band you want to explore. Click START to enable browser audio, then increase the volume gradually. Check mute and your computer’s audio output if you hear nothing.
  3. Find the frequency-entry box and check its units. In a kHz field, enter 1160 for 1160 kHz, or 14290 for 14.290 MHz. The spectrum shows signal level across frequency; the waterfall shows how signals change over time. Zoom in enough to separate nearby signals.
  4. Record the receiver’s name, URL and geographic location from its page. This is the location of the remote antenna and receiver. The transmitter can be somewhere else; you do not need to locate it.
  5. AM / DSB — choose the broadcast band. On the Utah landing page, select WebSDR1 ("Yellow") → AM Broadcast (1160 kHz).
  6. Select AM and keep the default AM filter initially. Look for a strong, narrow carrier peak in the spectrum, or a steady carrier line in the waterfall. Center the tuning on that carrier.
  7. Listen for understandable speech or recognizable music. If the starting channel is unclear, explore nearby broadcast channels until you find an intelligible signal.
  8. Zoom in around the carrier while speech or music is present. Look for signal energy on both its lower-frequency and higher-frequency sides. The carrier and both sidebands support identifying ordinary AM as DSB with a carrier.
  9. Save a screenshot showing the carrier, both sidebands where visible, frequency, AM setting and spectrum/waterfall. Record your audio and spectrum observations in the AM / DSB row of Table 2.
  10. USB — choose the 20-meter band. Return to the landing page and select WebSDR2 ("Green") → 20 meters. Select USB.
  11. Explore approximately 14.150–14.350 MHz. Look for narrow patches of activity that change while someone speaks. Amateur conversations can have gaps between transmissions; choose an active voice signal.
  12. Tune slowly across the signal. If the voice sounds unusually high or low, make smaller frequency adjustments until speech sounds natural. Use the receiver’s default USB filter initially.
  13. When correctly tuned, look for speech energy mainly above the tuned reference frequency. A strong continuous carrier is normally absent. The reference marks where the suppressed carrier would be, so do not require a visible carrier line.
  14. Save a screenshot while the speaker is transmitting, with frequency, USB setting and spectrum/waterfall visible. Record what you heard and the observations supporting USB in Table 2.
  15. LSB — choose the 40-meter band. Return to the landing page and select WebSDR1 ("Yellow") → 40 meters. Select LSB.
  16. Explore approximately 7.175–7.300 MHz. Look for active voice transmissions and tune in small steps until speech sounds natural. Use the receiver’s default LSB filter initially.
  17. When correctly tuned, look for speech energy mainly below the tuned reference frequency, usually without a strong continuous carrier. Compare its position with the frequency scale.
  18. Save a screenshot during speech, with frequency, LSB setting and spectrum/waterfall visible. Record your audio and spectrum observations in the LSB row of Table 2.
  19. Use the spectrum and audio together. The selected mode button alone does not identify the transmission. An ordinary AM broadcast can also be heard using USB or LSB because it contains both sidebands. Find separate single-sideband transmissions rather than submitting the same AM broadcast three times with different receiver settings.
  20. If a band is quiet or a signal is too weak to identify, choose another receiver covering that band from the Utah landing page or WebSDR directory. Record the receiver you actually use. Fading or a weak carrier alone does not prove that a signal is single sideband.
  21. For each of the three signals, record frequency with units, receiver name/location/URL, selected mode, an intelligible-audio observation and the spectrum evidence supporting the type. Caption all three screenshots with those settings and observation time, then close the receiver tabs when finished.

3. Investigate the Cellular Backup Link — Table 3

Evidence Photo

Cite dataset DC10-CELL-04. Include a readable spreadsheet summary, one representative SINR formula and the labeled SINR time plot; keep the full working spreadsheet rather than pasting all 1,296 rows.

  1. Open the Facilities acceptance-test report. Security Engineering has received a request to recommend an antenna location for the building’s cellular backup gateway. Read the brief, acceptance requirements and analysis goals.
  2. Download Attachment A from that report and import the CSV into Excel. It contains 432 scheduled tests per location, 1,296 total, over three days. Keep the records grouped by location and then time.
  3. Use each record’s S, I and N powers to calculate linear SINR and SINR in dB for the complete dataset. RSRP and RSRQ are already supplied. Keep full calculation precision and display results to two decimal places.
  4. For A, B and C, summarize the test count, on-time acknowledgement percentage, longest consecutive failure run, median RSRP and median calculated SINR in Table 3. Apply both acceptance requirements before rounding.
  5. Make one labeled time plot of calculated SINR for all three locations across all three days. Compare radio-quality changes with late or missing acknowledgements and inspect RSRQ near the failures.
  6. Recommend a location using delivery results, failure patterns and radio evidence. If multiple locations qualify, explain the tradeoff and a limit on your recommendation. Explain a case where radio quality does not establish dependable delivery. Assess whether deliberate interference is established, give an alternative explanation and propose a follow-up test.
  7. If you need help, expand “Analysis walkthrough — optional” in the Facilities report for equations, Excel formulas and chart setup.

Why This Lab Matters

  • Line coding lets a receiver recover bits but does not authenticate commands or prevent replay.
  • Remote receivers make signals observable from another location; a frequency, mode button or familiar voice alone does not authenticate the transmitter.
  • Power and quality evidence supports receiver placement and availability without proving the cause of interference.
