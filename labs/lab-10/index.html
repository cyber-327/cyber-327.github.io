Line Coding and Radio Reception

Read line-coded data on an oscilloscope, compare local and remote AM reception, and choose a cellular receiver location using signal-quality evidence

Learning Outcomes

By the End of This Lab

  • Compare four encodings of the same byte and recover an unknown byte from measured levels and transitions
  • Operate a local RTL-SDR and a remote WebSDR and distinguish observations from station-identity claims
  • Explain reception differences using location, antenna, noise and propagation
  • Analyze a three-day cellular backup-link log in Excel and recommend a placement using radio quality and timely alert delivery

The Big Picture

What You Are Doing

  1. Work through three independent activities; your assigned group determines the order.
  2. Use a Nano and oscilloscope to compare line codes and decode one unknown byte.
  3. Receive an AM broadcast locally and through a remote WebSDR, then compare the evidence.
  4. Investigate a supplied workplace report and 1,296 cellular test records to choose a backup-gateway antenna location. No phone is required.
  5. Submit an individual report after completing all three activities.

Before Lab

Preparation

  • Install SDR++ before lab using the linked macOS/Windows guide. You can check that the app opens without a dongle; receiver checks need one of the two shared dongles.
  • Have Arduino IDE available. Use the preloaded Nano; open Serial Monitor at 115200 baud with Newline selected.
  • Review the Lecture 25 line-code conventions and this week’s spectrum, propagation and cellular-quality terms.
  • Open the report. Your instructor supplies the rotation group, AM test frequency and cellular dataset. The procedure below gives the Northern Utah WebSDR access steps.

Measurement Map

What Each Voltage Tells You

CH1
D9 encoded data. CH2: D2 frame start. Both probe grounds: Nano GND.
ASCII lookup for the unknown
H=48, I=49, J=4A, K=4B, L=4C, M=4D, N=4E, O=4F (hex). Group decoded bits into two four-bit hex digits before using the lookup.

Follow These Steps

Lab Walkthrough

1. Read the Line Codes — Table 1

Evidence Photo

Save NRZ-M and Manchester reference traces and your unknown-byte trace. Show both channels, time scale and marker; include the eight-bit decoding.

  1. Connect the preloaded Nano to USB. Select its port in Arduino IDE, open Serial Monitor at 115200 baud with Newline selected, and send HELP. Leave the firmware installed.
  2. Use two 10× probes and set both scope channel probe factors to 10×. Connect both ground clips to Nano GND. Connect CH1’s tip to D9 (encoded data) and CH2’s tip to D2 (frame-start marker). These are scope connections only; do not connect an external generator.
  3. Enable both channels in Normal time mode with DC coupling. Start at 2 V/div and 10 ms/div. Position both traces so you can distinguish LOW near 0 V from HIGH near 5 V using each channel’s zero reference.
  4. Set Trigger to Edge, source 2, rising slope. Turn the physical Trigger Level knob until the upper-right readout is about 2 V. Choose Horiz → Time Ref → Left and set horizontal delay to 0 s. Keep at least eight divisions to the right of the trigger.
  5. Send FRAME REF and CODE NRZ-L, one command per line. The byte repeats automatically. Use Run/Stop to freeze a stable capture, or Single to acquire the next frame. The CH2 pulse is a 1 ms frame marker, not a bit clock.
  6. The marker’s rising edge is time 0. Read eight consecutive 10 ms bit intervals, ending at 80 ms. Read NRZ levels at 5, 15, 25, 35, 45, 55, 65 and 75 ms. Count intervals, including repeated levels, rather than counting pulses.
  7. The reference is ASCII A: hex 41, bits 01000001, most significant bit first. NRZ-L uses HIGH for 1 and LOW for 0. Record the eight observed levels in Table 1.
  8. Send CODE NRZ-M. The data starts LOW immediately before the marker and changes at a bit’s start for 1; 0 holds its level. Read the level in each interval and compare it with the previous level, starting from LOW. Record the result.
  9. Send CODE NRZ-S. Its initial level is also LOW, but 0 changes the level at the bit’s start and 1 holds it. Record the eight observed levels.
  10. Send CODE MANCHESTER. A 1 changes LOW → HIGH at the middle of its bit; a 0 changes HIGH → LOW. Read each interval’s first and second halves, near 2.5 and 7.5 ms after its start. Ignore transitions at bit boundaries when deciding its value.
  11. Save a reference capture for NRZ-M and one for Manchester. Explain which code guarantees a transition within every bit and how that helps the receiver keep time.
  12. Send FRAME UNKNOWN. This selects a different byte encoded in NRZ-M, with initial level LOW. Capture all eight intervals. Record levels, decoded bits, hex and ASCII. Use the ASCII reference below; the console does not reveal the unknown byte. Save the original trace as evidence.
  13. Before leaving, send FRAME REF and CODE NRZ-L. Disconnect the scope probes and leave the board ready for the next group.

2. Compare Local and Remote AM Reception — Table 2

Evidence Photo

Save one local and one remote spectrum/waterfall image, with receiver location, frequency, mode, time and relevant settings. Caption any fallback as supplied evidence.

  1. Use the two prepared RTL-SDR computers. With three teams, two begin on local receivers while the third uses WebSDR. Swap roles when directed so every team collects local and remote observations. With two teams, both can begin locally and then switch to WebSDR. Compare your observations and reset the equipment before leaving.
  2. At a local receiver, confirm the antenna is connected. In SDR++, select Source → RTL-SDR, refresh the device list and choose the assigned dongle. Keep Bias-T off. Use the prepared V3 direct-sampling settings; the installation guide explains Q branch and automatic direct sampling.
  3. Enter the assigned carrier frequency in the large frequency display at the top. SDR++ displays Hz; for example, 1,000 kHz is 1,000,000 Hz. Choose AM in the Radio section, start with a 10 kHz receiver filter, press Play and increase the audio volume gradually. Keep the instructor’s prepared gain settings.
  4. Receiver filter width is the frequency range passed to the demodulator. For a centered AM filter with a total width of 10 kHz, tuning to 1000 kHz passes approximately 995–1005 kHz.
  5. A wider filter can preserve more of the wanted sidebands, but also admits more noise and nearby signals. A narrower filter can reduce unwanted reception, but may cut off wanted sideband content and make the audio sound muffled. This setting changes what the receiver processes; it does not change the transmitted signal’s bandwidth.
  6. Listen for a spoken station name, callsign or location. Record the time, tuned frequency, antenna/location, mode, audio clue and anything that affects clarity. A program name alone may be shared by several stations.
  7. Zoom the spectrum enough to see the carrier and nearby sidebands. Estimate the visible signal width when possible and state its uncertainty. Record the receiver filter width separately: the selected filter is not a measurement of transmitted bandwidth. Save a spectrum/waterfall screenshot with the frequency and settings visible.
  8. Open Northern Utah WebSDR. Under WebSDR1 ("Yellow"), select AM Broadcast (1160 kHz).
  9. Select AM and enter the same carrier frequency used on the local RTL-SDR, using the frequency field’s displayed units (often kHz). Replace the shortcut’s starting frequency of 1160 kHz with the assigned frequency.
  10. Click START to enable browser audio, then adjust the volume.
  11. Start near a 10 kHz total receiver filter width if available. Otherwise use the AM default and record its actual width.
  12. Confirm and record the remote receiver’s location, tuned frequency and actual receiver filter width. WebSDR uses the remote receiver and antenna; it does not need your USB dongle.
  13. Record the same observations and save a screenshot showing the remote receiver, tuned frequency and spectrum. If reception is absent or unclear, record that honestly; use the instructor’s alternate frequency or supplied fallback capture when directed.
  14. Do these receivers appear to be receiving the same station? Explain your evidence. Why might the sound and spectrum look different? State same station, different stations, or not enough evidence. Matching frequency or matching syndicated audio alone does not prove it is the same transmitter.
  15. Explain two plausible causes of a reception difference using your observations: receiver location, antenna, interference, propagation or receiver settings. Internet buffering can delay remote audio; that delay is not a measurement of radio propagation time. A poor signal alone does not establish an attack.
  16. Do not compare the numerical signal levels across these receivers as calibrated power. SDR++ commonly displays dBFS and remote meters can use another scale. This V3 AM activity does not require changing RF gain, which may be unavailable in direct sampling.
  17. Stop SDR++ before unplugging a dongle. Restore the assigned frequency and settings, close your WebSDR tab and return headphones for the next group.

3. Investigate the Cellular Backup Link — Table 3

Evidence Photo

Cite dataset DC10-CELL-04. Include a readable spreadsheet summary, one representative SINR formula and the labeled SINR time plot; keep the full working spreadsheet rather than pasting all 1,296 rows.

  1. Open the Facilities acceptance-test report. Security Engineering has received a request to recommend an antenna location for the building’s cellular backup gateway. Read the brief, acceptance requirements and analysis goals.
  2. Download Attachment A from that report and import the CSV into Excel. It contains 432 scheduled tests per location, 1,296 total, over three days. Keep the records grouped by location and then time.
  3. Use each record’s S, I and N powers to calculate linear SINR and SINR in dB for the complete dataset. RSRP and RSRQ are already supplied. Keep full calculation precision and display results to two decimal places.
  4. For A, B and C, summarize the test count, on-time acknowledgement percentage, longest consecutive failure run, median RSRP and median calculated SINR in Table 3. Apply both acceptance requirements before rounding.
  5. Make one labeled time plot of calculated SINR for all three locations across all three days. Compare radio-quality changes with late or missing acknowledgements and inspect RSRQ near the failures.
  6. Recommend a location using delivery results, failure patterns and radio evidence. If multiple locations qualify, explain the tradeoff and a limit on your recommendation. Explain a case where radio quality does not establish dependable delivery. Assess whether deliberate interference is established, give an alternative explanation and propose a follow-up test.
  7. If you need help, expand “Analysis walkthrough — optional” in the Facilities report for equations, Excel formulas and chart setup.

Why This Lab Matters

  • Line coding lets a receiver recover bits but does not authenticate commands or prevent replay.
  • Two receivers can hear different signals on the same frequency; waveform or audio similarity alone does not authenticate a transmitter.
  • Power and quality evidence supports receiver placement and availability without proving the cause of interference.
