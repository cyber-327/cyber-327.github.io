01 / Request

Due to a recent outage of our wired Internet connection, several security alerts reached the monitoring center late. To prevent this from happening again, we will install a cellular backup gateway for emergency transmission of security alerts.

Our team has proposed three locations for installation. We have conducted tests at these locations across a three-day period. At your earliest convenience, please review the collected data and provide us with a recommendation on where to install the gateway antenna.

02 / Test conditions

Three identical gateways with the same firmware, carrier service and antenna type were tested simultaneously. A was in the security office, B in the equipment room and C at an upper-floor window. All test messages used cellular service; the wired connection did not carry them.

The test ran from November 2, 2026 at 00:00 through November 4 at 23:50. Each gateway sent one scheduled test message every 10 minutes: 432 per location and 1,296 in total. All timestamps use MST (UTC−07:00). Records are grouped by location and then time. Each gateway retained its log locally, including records without an acknowledgement.

Each message has a unique ID. ACK means a matching acknowledgement was observed within 60 seconds; ack_delay_s records the elapsed time. TIMEOUT means none was observed within that window. A blank timeout delay is unknown, not zero; the outgoing message or the acknowledgement may have been delayed or lost.

The ten-minute schedule applies to acceptance testing. Operational security alerts are sent when events occur.

03 / Acceptance requirements

  1. At least 99.0% of scheduled messages at a location must receive an acknowledgement within 10.00 seconds, inclusive.
  2. There must be no two consecutive failed tests at that location. A late ACK (over 10.00 seconds) and a TIMEOUT both count as failed tests.

Both requirements must be met. Apply the percentage requirement before rounding.

04 / Operations notes

  • Loading-dock activity and nearby electrical equipment usually increase between 14:00 and 15:00 each day. No controlled equipment on/off test was recorded.
  • A routine gateway-management job was scheduled for November 3 between 11:00 and 12:00. Per-device completion logs were not retained.
  • No confirmed interference incident or transmitter identification was recorded. These observations are leads for investigation, not established causes.

06 / Analysis requested

  1. Calculate linear SINR and SINR in dB for every test record using its signal, interference and noise powers.
  2. For each location, report the test count, percentage acknowledged on time, longest run of failed tests, median RSRP and median calculated SINR.
  3. Plot calculated SINR against time for all three locations across the complete three-day period. Compare changes in radio conditions with late acknowledgements and timeouts; inspect RSRQ near the failures.
  4. State whether each location meets both acceptance requirements, then recommend an antenna location using the delivery results and radio evidence.
  5. Discuss one case where radio quality does not explain dependable alert delivery. Assess whether the records establish deliberate interference, give an alternative explanation and propose a follow-up test.
  6. Include a readable spreadsheet summary, one representative SINR formula and the labeled time plot with your recommendation. Keep the full working spreadsheet; do not paste all 1,296 rows into the report.

1 / Import the log

Import the CSV into Excel with its header row. Keep the eleven supplied columns in A–K and the records ordered by location, then timestamp. All 1,296 records occupy rows 2–1297. If your Excel locale uses semicolons, replace formula argument commas with semicolons.

2 / Calculate SINR for every record

Wanted-to-unwanted power ratio

SINR=SI+N

Express the power ratio in decibels

SINRdB=10log10(SI+N)

On-time acknowledgement percentage

Pon time=Non-time ACKsNscheduled tests×100%

S, I and N are compatible powers in pW; the common unit cancels in the ratio. RSRP and RSRQ remain reported inputs. Do not substitute RSRP in dBm, total-band RSSI or an uncalibrated spectrum peak for S.

Add L1 = linear_sinr and enter in L2:

=G2/(H2+I2)

Add M1 = sinr_db and enter in M2:

=10*LOG10(L2)

Fill both formulas through row 1297. Retain full cell precision and display results to two decimal places. A negative dB result means the wanted power is below interference plus noise; it does not mean negative power.

3 / Check timely delivery and consecutive failures

Add N1 = on_time. In N2 enter:

=IF(AND(K2="ACK",ISNUMBER(J2),J2<=10),1,0)

One means on time; zero means a failed test. ISNUMBER prevents a blank timeout delay from counting as a fast acknowledgement.

Add O1 = failure_run. In O2 enter:

=IF(N2=1,0,IF(B2=B1,O1+1,1))

Fill both formulas through row 1297. The run resets after a success or a new location. A late ACK and a TIMEOUT both extend it. Restore location/time order if you sort the log.

4 / Summarize each location

Use the formulas below for A; substitute B or C where appropriate. Format the on-time fraction as a percentage with two decimal places and apply the 99.0% requirement before rounding.

Scheduled test count
=COUNTIF(B2:B1297,"A")
On-time fraction
=COUNTIFS(B2:B1297,"A",N2:N1297,1)/COUNTIF(B2:B1297,"A")
Longest failure run
=MAX(O2:O433)
Median RSRP
=MEDIAN(E2:E433)
Median calculated SINR
=MEDIAN(M2:M433)

Location ranges: A = rows 2–433; B = 434–865; C = 866–1297. Use each location’s range for MAX and MEDIAN. The median is the middle reported or calculated value, not an average linear power. Inspect RSRQ near delivery problems as additional evidence.

5 / Plot and interpret

Make one line chart. Use A2:A433 for the horizontal time axis and three series from M2:M433, M434:M865 and M866:M1297. The three locations share the same scheduled times. Label the vertical axis “Calculated SINR (dB)” and name the series A, B and C. Include all three days.

Compare drops and stable periods with the acknowledgement records. A strong or clean downlink reading does not establish that the outgoing alert, return acknowledgement or monitoring application worked. Ten-minute sampling identifies failed scheduled tests, not an outage’s exact duration.
